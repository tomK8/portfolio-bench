Highlighted rows sit on the wrong side of their own limit — a buy whose limit is at or above the market, or a sell at or below it. A resting order in that state should already have executed, so either the Current price is stale (nothing keeps an order-only symbol's feed warm between ticks) or the broker export pre-dates the fill.

Rows marked pre-market 13:58 / after-hours 21:40 are priced off an extended-hours quote — used because it's the newest price available, and the alternative is a close that's hours older. The time is the print time, and it's always shown: these sessions trade thinly, so a quote can sit unchanged for a quarter of an hour and still be the latest one Yahoo has. Those rows never raise the amber through-limit flag either — a resting regular-hours order doesn't fill outside regular hours, so sitting through the limit on a thin pre-market print isn't the same signal.

P(N) asks whether each order fills before it expires: N is that order's own trading sessions to expiry, or 90 sessions for a GTC order, which has no deadline of its own. Sessions, not calendar days — the unit P(5d) uses and the one σ is scaled in (√sessions); type 5 into a row's box and it reproduces that row's P(5d).
The volatility is forecast for the horizon, not measured over a trailing window of the same length. Realized vol mean-reverts, so a name fresh off a violent fortnight would otherwise be priced as though the next quarter stays violent, and a sleepy one as though it stays asleep. What the model needs is the expected average variance over the sessions ahead, so current state (RV20) is blended toward a long-run anchor (RV250) with the weight decaying at a 20-session half-life: var_N = var_LR + (var_now − var_LR)·(1 − e^−κN)/κN. Hover any cell for the σ it used and how much of it was current state. The small figure under each probability is the same estimate computed off RV10 and RV30 instead: when the low end already clears the threshold you are deciding against, the call survives the vol input being wrong — when only the high end does, it needs a second look.
Read the column as indicative rather than calibrated. The model assumes no drift, a fair convention over a week and an assumption over a quarter. Drift is on: equities and equity funds carry an 8%/yr total return, less each name’s own forward dividend yield to reach the price drift a limit is actually touched by — a high-yielder nets to near zero, a non-payer keeps the whole figure — while gilts and bullion carry none. A buy limit below the market therefore reads lower than it would driftless and a sell limit above it reads higher. The figure each row was given is on its hover and in the Excel Drift (annual) column. One consequence worth knowing — P(5d) is no longer 2·Φ(−|σ→lim|). σ→lim is a distance, and only the driftless branch is its exponential. Earnings variance is on: a scheduled print inside a row's horizon adds its own move in quadrature (6% for a single-name equity), so a quiet name with a report due prices higher than its trailing volatility alone would say. Rows whose date could not be obtained are named in the warnings above and are left unadjusted — never estimated from a quarterly cadence, which would be indistinguishable on screen from a real date. Push a row much past six months and the figure is marked to say so. Every row priced here is written to a calibration log (~/log/portfolio-bench-touch-calibration.log) with its σ, horizon and forecast, so these probabilities can be scored against actual fills later.

Click any row for the price popup — chart, momentum, vol term structure and fundamentals, the same one the Live and Watchlist tables open. Rows whose instrument isn't mapped to a ticker yet aren't clickable; map them above and they will be.

Status is normalised: the three brokers write six spellings between them (Dealt / Executed / EXECUTED, CANCELLED / Canceled), so each row shows the outcome in one vocabulary and the broker's own word is on hover.
